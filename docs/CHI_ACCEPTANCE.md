## Full routes and a correction to earlier claims

The Original route reaches the ending from a fresh game with its Legacy default.
The Updated route starts with its Enhanced default, **chooses Legacy through the
ordinary Settings menu**, completes all training and the physical invasion
escape, forms a five-person party, buys the required apprenticeships,
earns the disk/password prerequisites and completes all eleven cache doors,
map room and ending. Both routes use only ordinary inputs and the owner's
authorized money shortcut. No save import, quest/coordinate/rank/RNG editing is
used. Their original-derived observations stay in ignored private evidence.

**Correction:** replaying `ordinary-fresh-campaign.actions` in default Enhanced
Updated mode was previously described too broadly as a full campaign. That input
stream matches the built-in Updated behavior without a fault, but does not
complete training. Identical inputs do not win both rule sets. The new acceptance
asserts an actual ending for each dedicated route. At that gate a complete
Enhanced-only campaign walkthrough was **UNKNOWN**. It is now separately
verified by the follow-up linked above; the earlier fixtures retain their
declared rules. Enhanced defaults, edited missions, combat rules and Updated
units also have focused checks. Legacy selection remains
a supported feature of Updated; the importer does not change its default.

## Reproduce and review

Keep proprietary observations under ignored `work/`; do not commit imported
projects, text, pixels, private saves or traces. The combined harness uses fresh
imports and reports each declared checkpoint separately:

```sh
python3 tools/chi_acceptance.py --output work/chi-import/acceptance-new
python3 tools/chi_acceptance.py --output work/chi-import/acceptance-new --windows
```

The first command generates the Updated input route locally. `--updated-route
PATH` reuses a retained private route while still checking completion and parity.
`--windows-details` resumes service/spatial checks only after retained baseline,
mission and bridge Windows evidence passed. A failed run retains its failure;
use a new directory for a new complete run.

Private retained campaign evidence: `work/chi-import/c45-verified/`, with
`evidence.json`, both complete states/frames/saves/BLD traces, per-edition source
coverage, service/mission/spatial examples, bridge artifacts and Windows reports.
The initial failed attempt is retained at `c45-acceptance/`; its Updated ending
assertion exposed the old overstatement. The Legacy route generator and native
route planners load real project saves and emit ordinary keys only.

Setup, GUI, Python/native logs and packaged checks are recorded under
`work/chi-import/c5-work/`. See [TESTING.md](TESTING.md),
[import/recovery](CHI_IMPORT.md) and [reconstruction](CHI_RECONSTRUCTION.md).

## Distribution and boundaries

`release_guard.py` inspects actual staged blobs, package directories and archive
members against source hashes, cache signatures, private CHI document formats,
known original tile pixels, declared origin and the distribution inventory.
Checks reject renamed caches/files, nested private documents, unknown origins,
traversal, symlinks, duplicate/missing entries and tampered inventory bytes.
Detection cannot license or identify every altered asset with stripped origin.

Recipes regenerate original bases locally and store edits/references, not a
redistribution of the imported resource set. Last Beacon's clean indexed example
retains independent placeholders; local reconstruction restores the 20 recorded
original bases. The owner's separate edited working files are preserved. Old
Git history has not been rewritten.

Native record/tile conventions, map slots, service handlers and the explicitly
supported quest adapters remain engine contracts. New engine mechanics and
additional native adapters require implementation; arbitrary scripts cannot
borrow another service's context. No known required original opcode is silently
ignored. Existing DOS fidelity approximations remain documented in the prior
system-specific evidence.
